## 1. 研究问题与假设

**问题**：在智能体评测中，用户模拟器是"测量仪器"。当被测用户说中文而非英文时，同一套智能体、同一批任务，其**被测得的分数与排名**会如何变化？

**H1（易化效应）**：中文条件下，模拟用户的表达更简短、更少澄清，智能体被**测得更高**的成功率。
**H2（难度效应，与 H1 竞争）**：中文条件下，模拟用户与英文目录之间的跨语言映射负担提高，智能体被**测得更低**的成功率。
　（H1 与 H2 方向相反，谁占优正是要测的东西；不做单侧预设。）
**H3（排名失真）**：语言切换导致的分数变化**不是各智能体等量的**，因此会改变智能体之间的相对排名。
**H4（模拟器依赖）**：语言带来的分数变化幅度**依赖模拟器厂商/档位**，故"用哪个模拟器"本身会调节结论。
**H5（机制）**：语言效应主要落在"该说的话没说到"（输出侧）还是"数据库终态错"（动作侧），可分解归因。

## 2. 设计与操纵

**单因子操纵：用户侧语言（en / zh）**，两水平。

- **只变用户侧**：模拟用户读到的指令语言、其系统提示词语言、其发言语言。
- **保持不变**：智能体的系统提示词（τ-bench retail wiki）、工具定义、数据库、评分器 —— 全部沿用 τ-bench 英文原样。
- 这对应"面向中文用户的跨语言客服"这一真实场景，且把差异唯一地归因到语言本身。
- 中英两套模拟用户提示词为**逐条忠实翻译**（条目数、顺序、语气强度一一对应），对应关系见 `simglot/harness/prompts.py` 末尾对照表。

**设计网格**（E2 主矩阵）：

```
30 条任务 × 2 语言 × 6 个模拟器 × 4 个智能体 × 3 个重复种子 = 4,320 集
```

**重复次数 3 是 W4 试点逼出来的硬要求**，而非可选项：见第 7 节，智能体存在约 15–20% 的"轨迹崩塌"率，每格只跑 1 次会让约 15% 的格拿到崩塌值（几乎必为失败），系统性压低成功率。按 15% 崩塌率，每格重复 3 次时"3 次全崩"的概率降至 0.34%。

若因额度或时长需缩减，缩减顺序**按试点实测的效应量重排**如下（试点发现模拟器效应 27pp 远大于语言效应 10pp，故语言与模拟器维度优先保护）：

1. **先降智能体 4→2**（得 2,160 集）——智能体是唯一在试点中未见显著效应的维度；
2. 再降任务 30→20（得 1,440 集），并在正文说明任务集缩小带来的外部效度限制；
3. **重复种子固定 3 次不动**——它是控制崩塌污染的唯一手段；
4. **语言维度与模拟器维度全程不动**——它们是本研究的主效应与主交互。

## 3. 材料

### 3.1 任务帧的确定（预注册的排除标准）

τ-bench retail 测试集 115 条中，先做**任务健康度审计**（`scripts/audit_tasks.py`，纯规则、零模型调用）：

- **A 类（19 条）真值动作回放报错**：任务自身不可解（`user not found` ×10、`product not found` ×3、`order not found` ×2、支付方式不自洽 ×2、非已送达订单不可换货 ×1、礼品卡余额不足 ×1）。其"正确终态"退化为"什么都没变"，**零动作的智能体自动满分**。
- **B 类（5 条）真值不含写动作且无输出约束**：同样零动作即满分。
- 其余 **91 条为可评分帧**（89 条真值会改库 + 2 条只读但有输出约束）。

> 该排除是**预注册决定**：凡"零动作即满分"的任务一律排除，判据客观且可复算（`data/task_health.json`）。

### 3.2 E1 任务子集（抽样规则）

- 从 91 条可评分帧中，按 **(意图族 × 复杂度) 联合分层**抽取 **N = 30**。
  - 意图族（互斥、按优先级）：transfer → cancel → items+address → items → address → payment → none
  - 复杂度（按真值工具动作数）：0–1 / 2–3 / 4–5 / 6+
- 配额在"每族保底 1 条"的硬约束下，用**确定性局部搜索最小化两个边缘分布的偏差**（算法见 `scripts/sample_tasks.py::allocate`）。
- **随机种子：20261007**（脚本同参可原样复现）。
- 实测对齐：复杂度四档最大偏差 1.4pp；意图族除帧内仅 1–2 条的稀有族（transfer / payment / none，保底 1 条所致）外最大偏差 2.7pp。

### 3.3 中文任务套件（E1 产物）

30 条中文指令在 `data/tasks_zh.json`，由研究者撰写，遵循：

- **逐字保留**：姓名、邮箱、订单号、邮编、金额、商品变体 ID、技术规格（`i9`、`256GB SSD`）。
- **译成自然中文**：商品名、选项值、城市州名、人设与情绪词、条件决策树、行为约束。
- 商品名与选项值的**跨语言映射负担被有意保留**——那是本研究要测的能力，不是缺陷。

**两轮独立校验**（均记录在案）：

1. **自动校验**（`scripts/build_zh_suite.py`）：不变项逐字保全、数字保全、无游离英文、覆盖完整、长度合理 → 0 硬错误。
2. **回译校验**（`scripts/backtranslate_check.py`）：两个**不同厂商**的模型（glm-5.3、deepseek-v4.1-flash）各将中文译回英文，研究者逐条裁决 → **30/30 语义一致**。过程中发现并修正 2 类漂移：
   - `water bottle` 一度译作"水壶"，两个回译模型**都**回译为 `kettle`，而库中 `Water Bottle` / `Electric Kettle` / `Tea Kettle` 三件并存 → 改为"水瓶"。
   - `Texas` 一度译作"德州"，与山东德州市同名 → 改为"得克萨斯州"。

- 另有 **18 条歧义**逐条留档（`data/tasks_zh.md`），供讨论章节使用。

## 4. 评分口径

**纯规则、零模型调用**，中英两臂共用同一套匹配逻辑（`simglot/harness/scoring.py`）。

- **动作侧 `r_actions`**：智能体跑完后的数据库终态哈希 == 回放真值动作后的终态哈希。**逐字复刻 τ-bench**，以保证与已发表基线同尺（一致性已验：60/60 格）。
- **输出侧 `r_outputs`**：任务要求的每个输出字符串，都出现在某条回应中。
  - 匹配前做 **NFKC 归一 + 去千分位逗号 + 小写**（全角数字、千分位写法不再造成假阴性）。
  - 语言相关输出项使用**预注册别名表**（`data/output_aliases.json`）：只登记原词本身的等价说法，不新增语义要求；不收录长度 < 2 的别名；**中英两臂同时生效**。
- **总分 `reward = r_actions AND r_outputs`**，与 τ-bench 口径一致。
- 两个分量始终分别记录，用于机制归因（H5）。

> 必要性已在采样集上验证：3 条含英文输出项的任务，**旧匹配器在中文回答下 100% 误判**——若不修，测出的"中文惩罚"会是评分器假象。

**评分器三检**（`scripts/check_scorer.py`，结果存 `logs/`）：检1 与 τ-bench 一致 60/60；检2 假阴性修复有效；检3 43 个不放水用例全过（空回应、零动作、不存在的数字均判负）。

## 5. 排除标准与预分析决定

- 任务级：第 3.1 节的健康度筛除（24 条），**在抽样前**完成，与实验结果无关。
- 集级：运行失败（异常或 API 报错）的集**保留在数据中并单独报告**，不静默丢弃；主分析在"完整集"上进行，另报"仅成功集"作为稳健性检验。
- 模拟器发言被截断的轮次：`transcript.json` 中 `truncated_final = true` 的集**标记并单独报告**。
- **轨迹崩塌（预注册量，W4 试点新增）**：存在 ≥5 个连续 `respond` 步骤，每步 `completion_tokens ≤ 2`，即判为崩塌。该现象由试点发现（`reports/w4_pilot_report.md` 第 3 节），特征是智能体只吐"好的/非常/让我"一类碎片且不再发出工具调用，直至撞满步数上限；`finish_reason = stop`（非截断），且在温度 0 下不可复现。**处理规则预先声明**：主分析纳入全部集，另报剔除崩塌集后的结果作为敏感性检验；崩塌率本身作为一个因变量报告。
- 不做：不做多重比较校正后的显著性狩猎；主效应与机制分解的假设先于数据固定（即 H1–H5）。

## 6. 分析计划

**因变量**：

1. **成功率**（0/1 的均值），按语言分臂。
2. **语言敏感度指数 LSI**（本研究提出）：
   $$LSI = \frac{|S_{zh} - S_{en}|}{S_{en}}$$
   其中 $$S$$ 为该臂成功率。**LSI 只作分层汇总的描述量，不作主结果**——W4 试点显示它极不稳定（首轮 0.40、n=60/臂 时 0.12），单看它会把抽样噪声误读成效应。
3. **主结果：语言 × 模拟器的交互**。试点中模拟器造成的分数差（27pp）近三倍于语言（10pp），且"哪个模拟器更严格"在两种语言下**方向相反**；故 E2 以交互项而非语言主效应为主要结论。
4. **排名失真**：在英文臂与中文臂分别对 4 个智能体排名，报告 **Kendall τ** 与排名变动。
5. **机制分解**：`r_actions` 与 `r_outputs` 失败率的语言差异（H5）。
6. **轨迹崩塌率**（试点新增）：按语言、按模拟器分臂。
7. **工具参数保真度**（试点新增）：智能体传给工具的身份参数若在指令、用户发言、智能体回复**及全部工具返回**中均未出现，即判为编造。**披露要求**：报告该指标时必须附检测器定义与语料范围（试点初版因漏掉工具返回而误判）。
8. **成本**：每集 token 数、调用数、墙钟，按语言与模拟器分臂。

**模型**：以 `reward` 为因变量，拟合**混合效应逻辑回归**（语言 × 模拟器档位 × 智能体档位为固定效应，任务与任务×语言为随机截距），报告效应量与置信区间。**崩塌作为协变量纳入**。不做 p 值驱动的结论。

**预跑门槛**：若英文臂在任一智能体上的成功率低于 20%，视为任务子集对本代模型过难、区分度不足，**回到 3.2 重抽**（仅此一种情形允许改抽样，且必须重新冻结）。

## 7. 额度门控（W4 试点实测填入）

标定批次 `w4_repeat`：5 任务 × 2 语言 × 2 模拟器 × 6 重复 = **120 集**，全流程实测值如下。

| 指标 | 实测 |
|---|---|
| 每集 token | **105,510**（智能体 97,123 = **92.1%**；模拟用户 8,387） |
| 每集调用数 | **26.7**（智能体 16.1 + 用户 10.6） |
| 每集墙钟 | **61.5 s**（并发 8） |
| 英文 / 中文每集 token | 99,784 / 111,237（中文 +11%，来自更长的对话：17.0 vs 15.3 步） |
| 吞吐 | 并发 8 下约 **470 集/小时** |

**全矩阵（4,320 集）外推**：

- token 总量 ≈ **456,000,000**（约 4.56 亿）
- 机器时间 ≈ **9.2 小时**（并发 8）
- 调用次数 ≈ **11.5 万次**

**成本的不确定性来自轨迹崩塌**：正常集约 60k token，崩塌集可达 190k（2–4 倍）。上表均值已含这部分重尾。若按最坏情形（崩塌率取上界 20%）重估，token 总量约 5.2 亿。

> 占额比例：用户已确认额度充足（试点全程消耗占配额 <0.1%），故此处只记录实测换算关系，不设停机阈值；每批次结束后由 `scripts/analyze_runs.py` 汇总实际消耗备查。

## 9. 版本固定与可复现性

- 模型阵容（3 厂商 × 多档位 = 6 个模拟器）：`qwen3.8-max` / `qwen3.7-plus` / `qwen3.8-flash` / `deepseek-v4-pro` / `deepseek-v4.1-flash` / `glm-5.3`。
- 这些均为**滚动别名**：平台不提供带日期的快照名。因此**每次运行的日志都记录调用日期**，并在论文中说明"分数绑定的时间窗口"。
- 已知的平台强制行为（须在论文中披露）：**glm-5.3 的思考模式由平台强制开启，无法关闭**（传 `enable_thinking: false` 返回 400，原文 `The value of the enable_thinking parameter is restricted to True.`）。其思考 token 计入 `max_tokens`，故模拟用户侧预算按厂商分设（qwen/deepseek 200，glm 2000），并设"撞顶或空返回则按 3 倍循环扩容"的兜底。实测各模拟器**可见发言长度相当**（glm 82.7 字符 vs 其余 50–100），故该预算差异不构成行为优势。
- 全部随机源固定：抽样种子 20261007；生成温度 0；重复种子 0/1/2。
- **平台在温度 0 下并非确定性（W4 试点实测，须在论文中披露）**：同一实验格在完全相同的输入与参数下重跑，得到不同轨迹。证据：把 `#74 zh × glm-5.3` 崩溃点的上下文原样打回模型，两次答复不同；且该格首轮失败、同参数重跑通过。因此：
  - 本研究**不把单次运行当作可复现的证据**，每格重复 3 次并以集为单位汇总；
  - 所有比较均报告"格内 3 次重复"的分布，而非单次取值；
  - 论文中"分数"一律指该时间窗口内的重复均值，并说明平台不提供确定性保证。

## 10. 已知局限与不做的事

- **不是**对真人用户的测量。本研究测的是"模拟器在被要求说中文时行为如何变化"，不能直接推及真人中文用户。真人基线（Sim2Real 63.6%）仅用作外部锚点。
- **不是**中文能力的评测。任务集来自英文原生 benchmark，中文版是重建而非原生设计，任务层面的文化效度不在本研究范围内。
- **不做**跨 benchmark 的泛化声明：结论只在 τ-bench retail 域、本任务子集、本时间窗口的模型上成立。
- 生态仅限于本账号实际可用的 3 家厂商；不得表述为"国内模型的普遍行为"。
- **不做"中文惩罚"的单向断言**：W4 试点在 n=60/臂 下测得语言差 −10pp、Fisher p=0.27，**不显著**；首轮 n=10/臂 时的 −40pp 经同参数重跑证伪。本研究只报告带置信区间的估计，不下"中文更难"的方向性结论，除非 E2 的交互模型支持。
- **不把轨迹崩塌解释为语言效应**：崩塌在两臂均约 13–18%（p=0.62），是模型自身的退化吸引子，与语言无关；论文中必须与语言效应分开陈述。
