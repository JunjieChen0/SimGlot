# 预言机完整性测试套件（Oracle Integrity Audit Kit）

> **这是 E0 的交付物**：把「我们在一份基准的评分器里发现了一个缺陷」升级为
> 「**我们给出了一套可复用的测试方法，并用注入的已知缺陷证明了它的检测能力**」。
> **零模型调用、零网络、零密钥**——全部只读 v1.0 的归档与 vendored 代码。
>
> **状态：已完成（2026-10-09）。** 三个目标上结论一致：**特异性**（C0 全绿，无假阳性）与
> **灵敏度**（7 类注入缺陷全部被检出）均通过，且每类缺陷对应到一个**最小检测器**（见 §4）。

---

## 1. 它解决什么问题

Agent 评测装置本身就是软件：它跑一套**测试用例**（任务），驱动一个**测试输入生成器**（用户模拟器），
并用一个**测试预言机**（reward / scoring function）判定通过与否。软件测试领域早就知道
**预言机缺陷**（oracle problem）与**抖动测试**（flaky tests）是质量的主要来源——但 Agent 评测社区
很少把评测装置当作被测对象来审计。

本套件给出**八个检测器**，分两族，检查一个预言机是否可信：

| 族 | 编号 | 性质 | 一句话 |
|---|---|---|---|
| 不变量 | **INV-1** | 状态保持 | 直接调用打分函数**不得改变**被判分状态 |
| | **INV-2** | 重复评分一致 | 同一环境连评两次，判定与状态都必须相同 |
| | **INV-3** | 顺序无关 | 判定不得依赖各集被打分的**先后** |
| | **INV-4** | 异常路径不泄漏 | 内部抛异常时状态必须还原、异常必须外传 |
| | **INV-5** | 结束步状态稳定 | 会话结束步**不得改变数据库状态**、不得留下多余动作 |
| 对照 | **CTL-1** | 负对照 | ①什么都没做 ②说了该说的输出但没写数据库 —— **都必须判不通过** |
| | **CTL-2** | 正对照 | 参考解 + 说全输出 —— **必须判通过** |
| | **CTL-3** | 格式容忍 | 输出写成等价写法（千分位 / 声明过的别名）仍应通过 |

**INV-5 是本研究头号缺陷的根因不变量**：一旦预言机在打分时把环境留在参考解上，
结束步前后的数据库散列就不再相同——**不需要任何下游代码配合**就能看见，
比「事后由 harness 第二次读取」这一具体集成路径更早、更一般地报警。

**两族不可互相替代**：C5/C6（饱和、忽略数据库）只有对照抓得到；C1/C4（状态污染、顺序依赖）
只有不变量抓得到。§4 的矩阵证明这一点。

## 2. 接口契约（为什么这算「方法」而不是「个案」）

套件对一个待审计对象只要求四条鸭子类型契约：

```
make(task_index)        → 一个干净环境
state(env)              → 被判分状态的内容签名（可比较）
oracle(env, task_index) → 打分，返回 Verdict(reward, r_actions, r_outputs)
env_class               → 预言机所在类（注入时在其中替换 calculate_reward）
```

有意做成**不依赖 τ-bench 的形状**。仓库内提供三个目标：

| 目标 | 说明 |
|---|---|
| `tau-bench/retail` | 真实基准的预言机，本研究的主战场 |
| `tau-bench/airline` | **同一预言机实现、不同任务域**——用于跨域确认 |
| `synthetic/tiny` | ~50 行的最小域，接口同形，**自带可声明的等价写法**（供 CTL-3 使用） |

---

## 3. 故障注入（缺陷类别）

`oracle_variants.py` 把七类已知的预言机缺陷实现为可直接替换的 `calculate_reward`。
**每个变体只与正确实现差一维**，以免把多个缺陷的效果混在一起：

| 代号 | 缺陷 | 现实对应 |
|---|---|---|
| **C1** | `state_mutation`：重置数据库回放参考答案后**不还原** | τ-bench 的历史实现（本研究 D17 的头号发现） |
| **C2** | `exception_leak`：成功路径还原，**异常路径泄漏** | 「有 try 没 finally」 |
| **C3** | `actions_not_restored`：还原了 data，忘了 actions | 部分还原 |
| **C4** | `order_dependent`：跨集共享缓存 | 模块级 memo 的经典坑 |
| **C5** | `saturated`：恒定返回通过 | 「97% 通过」的标签把自己藏起来 |
| **C6** | `db_blind`：只看输出子串，忽略数据库终态 | 只查「说得对不对」，不查「做得对不对」 |
| **C7** | `strict_format`：输出匹配不做任何规范化 | 大小写/千分位/全角都不认 → **语言偏斜** |

**C0 = 不注入**（用对象自己的实现），是特异性对照。

## 4. 结果：缺陷类别 × 检测器

**三个目标给出同一张表**（τ-bench retail、τ-bench airline、合成域）——这正是「方法不是个案」的检验：

| 缺陷类别 | INV-1 | INV-2 | INV-3 | INV-4 | INV-5 | CTL-1 | CTL-2 | CTL-3 | 最小检出集 |
|---|:--:|:--:|:--:|:--:|:--:|:--:|:--:|:--:|---|
| **C0** 不注入（as-shipped） | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | **全绿 = 特异性** |
| **C1** 状态污染（不还原） | ✗ | ✗ | ✓ | ✗ | ✗ | ✗ | ✓ | ✓ | INV-1 / INV-5 |
| **C2** 异常路径泄漏 | ✓ | ✓ | ✓ | **✗** | ✓ | ✓ | ✓ | ✓ | **INV-4（唯一）** |
| **C3** 只还原数据、不还原动作 | ✗ | ✗ | ✓ | ✗ | ✗ | ✓ | ✓ | ✓ | INV-1 / INV-5 |
| **C4** 跨集顺序依赖 | ✓ | ✓ | **✗** | ✓ | ✓ | ✓ | ✓ | ✓ | **INV-3（唯一）** |
| **C5** 饱和（恒定通过） | ✓ | ✓ | ✓ | · | ✓ | **✗** | ✓ | ✓ | **CTL-1（唯一）** |
| **C6** 忽略数据库分量 | ✓ | ✓ | ✓ | · | ✓ | **✗** | ✓ | ✓ | **CTL-1（唯一）** |
| **C7** 严格匹配（语言偏斜） | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | **✗** | **CTL-3（唯一）** |

符号：✓ 未报警 ｜ ✗ 报警 ｜ · 不适用（该实现在探针下不经过内部执行路径）。

**三条结论**：
1. **特异性**：C0 在每个目标上全绿 —— 没有检测器误报（假阳性 0）。
2. **灵敏度**：7 类注入缺陷**全部**被检出，**无盲区**。
3. **两族不可互相替代**：C2/C4/C7 各只被**一个**检测器抓到；C5/C6 只有**对照**抓得到（不变量全过）——
   一个状态干净、方向错误的预言机骗不过 CTL，反之亦然。

**跨域确认**：C1 在 retail 与 airline **两个任务域**上都被 INV-1/INV-2/INV-4/INV-5/CTL-1 检出，
说明该缺陷类别不绑定于某一个任务集合。

见 `results/oracle_audit_matrix.txt`（人读）与 `.csv`（长表）。
复算：`python3 run_audit.py`。

**实测用时**：合成域 < 1 s；**τ-bench retail + airline 合计 ≈ 620 s（≈ 10 分钟；两次实测 608.6 / 626.3 s）**——
瓶颈是每次构造环境与每次打分都要重载完整数据库（retail 15.7 ms/次、airline 32.4 ms/次）。
用 `--targets synthetic/tiny` 可秒级自检；用 `--tasks 4` 可缩短耗时。

预期结论（**由矩阵本身给出，不在此处预设**）：
① C0 在每个目标上全绿（**特异性**，无假阳性）；
② 每个注入类别至少被一个检测器检出（**灵敏度**）；
③ 任何**无人能抓**的类别如实列为盲区。

## 5. 已知盲区（**必须如实写进论文**）

1. **输出接受集是「规格」而非「推断」**。CTL-3 只能检验「该接受而没接受」，
   前提是被审计对象**声明**了它接受哪些等价写法。τ-bench 的预言机**没有**这样的声明，
   故 CTL-3 在 τ-bench 上只覆盖千分位这一种格式化变体。
   本项目的 `harness.scoring.score` 另带 `data/output_aliases.json` 的双语同义表——
   那属于**另一层**（输出匹配规格），不在本套件的状态完整性范围内。
2. **这里审计的是基准自带的预言机**（`Env.calculate_reward`），不是本项目的 harness。
   后者已带 v1.0 的 try/finally 修补，把它当作「正确的参照」来审计没有意义。
3. **不覆盖语义级错误**：预言机可以状态干净、方向正确，却对某个任务的**真值标注本身**判错。
   那需要独立真值，超出本套件。
4. **不覆盖多线程/分布式预言机**（本套件是单进程、串行）。
5. **合成域是自证的**：它的价值在于证明接口不依赖 τ-bench，以及给 CTL-3 一个可声明的接受集，
   **不**构成独立的经验证据。

## 6. 用法

```bash
cd sqj/oracle_audit_kit
python3 run_audit.py                                   # 三个目标全跑
python3 run_audit.py --targets synthetic/tiny           # 秒级，先自检
python3 run_audit.py --targets tau-bench/retail --tasks 6
```

**离线约束**：经由 `_paths.py` 复用 v1.0 的 `scripts/_offline.py`——禁止 litellm 联网、
缺包时装禁用桩、不读任何密钥。可加 `SIMGLOT_OFFLINE_STUB=1` 强制走纯离线桩。

**只读保证**：本套件只**导入** v1.0 的 `vendored τ-bench` 与 `harness.scoring`，
从不写入 `simglot/` 下的任何文件。
